# 团队共享问卷模板接口约定（待后端确认）

本功能用于管理员把当前题目保存为团队共享模板、查看模板列表和详情，并把模板题目复制到岗位编辑表单。范围仅包含创建、列表、详情和应用；本期没有模板更新或删除接口。

**下列模板接口均为本次提出的前后端契约，不代表 Java 后端已经实现、部署或完成联调。** 后端由其他维护者负责，需先核对实际维护仓库、分支、网关路径、认证及角色枚举，再按本文实现或双方调整契约。公开候选仓库 `AUSIO2/FusionCareer-Backend` 是较早的 `/internal` 接口体系，角色为 `NORMAL`、`ADMIN`，且没有当前前端依赖的 `/user/me`；不能将其视为与当前前端兼容的后端，也不能据此宣称新增模板接口已可用。

## 路径、认证与持久化

前端统一 API 客户端位于 `src/lib/api.js`，默认前缀为 `/api`，通过 `VITE_API_BASE` 可调整；当前认证请求头为 `Fusion-Token`。模板客户端传入 `/admin/questionnaire/templates`，默认实际请求路径为 `/api/admin/questionnaire/templates`，不可重复拼接 `/api`。

| 方法 | 默认完整请求路径（均为拟议新增接口） | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/questionnaire/templates` | 查询团队共享模板列表 |
| `GET` | `/api/admin/questionnaire/templates/{id}` | 查询一个模板的题目定义 |
| `POST` | `/api/admin/questionnaire/templates` | 创建一个不可覆盖的模板快照 |

后端必须在每次请求中验证登录状态和管理员权限，包括列表和详情。普通学生账号不得读取或创建模板。当前前端使用 `ADMIN`、`SUPER_ADMIN` 管理角色；`SUPER_ADMIN` 是否存在、角色继承及团队共享边界须与实际 Java 后端对齐，不能只依赖前端隐藏按钮或相信请求中的角色字段。若部署有多个团队，后端按已认证账号限定团队，不接受客户端任意指定团队来绕过隔离。

模板须保存于服务端持久化存储，供同一授权团队的管理员跨浏览器、跨设备读取。前端不得以 `localStorage`、`sessionStorage`、静态示例或当前标签页内存冒充共享模板库；接口不可用时显示失败和重试，不切换为本地模板保存。当前页面内的临时编辑内容不构成已保存模板。

## 响应结构与 ID 精度

JSON 接口统一使用 `{ "code": 200, "message": "success", "data": ... }` 成功封装。成功状态和业务码都应为 `200`；失败必须使用明确的失败状态及业务码，不能在 HTTP 失败响应中返回 `code: 200`。

模板 ID 一律以非空 JSON 字符串返回、传递和比较。例如 `"9007199254740993"` 必须原样保留；Java `Long` 不能作为不安全的 JSON number 输出。数值在 `JSON.parse` 时已丢失的精度无法通过随后调用 `String()` 修复。模板、岗位、题目及文件等长整型标识均应遵守字符串传输约定，路径参数须编码后传递。

### 列表：拟议 `GET /api/admin/questionnaire/templates`

`data` 固定为数组，不使用分页对象或将数组另包在 `list` 中。无模板时返回空数组。每项仅包含摘要，`questionCount` 为正整数，`createdAt` 为服务端生成的含时区 ISO 8601 时间字符串。

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": "9007199254740993",
      "name": "运营问卷",
      "questionCount": 1,
      "createdAt": "2026-10-15T08:00:00Z"
    }
  ]
}
```

列表由服务端提供稳定排序，建议 `createdAt DESC` 并用唯一 ID 作为同时间的第二排序键。前端保留服务端顺序，不将本地插入顺序当成共享库排序。列表数量必须与详情中的真实题目数一致。

### 详情：拟议 `GET /api/admin/questionnaire/templates/{id}`

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": "9007199254740993",
    "name": "运营问卷",
    "questions": [
      {
        "sortOrder": 1,
        "title": "你擅长哪些运营方向？",
        "questionType": "CHECKBOX",
        "options": ["内容运营", "用户运营"],
        "required": true,
        "placeholder": ""
      }
    ]
  }
}
```

详情返回保存时的完整题目快照。模板不存在或不在当前账号可访问范围时，后端按已确认的权限策略返回 `404` 或 `403`，不可泄露其他团队内容；前端显示失败，不把缺失详情解释为空问卷。

### 创建：拟议 `POST /api/admin/questionnaire/templates`

请求为 `Content-Type: application/json`，正文只含 `name`、`questions`：

```json
{
  "name": "运营问卷",
  "questions": [
    {
      "sortOrder": 1,
      "title": "你擅长哪些运营方向？",
      "questionType": "CHECKBOX",
      "options": ["内容运营", "用户运营"],
      "required": true,
      "placeholder": ""
    }
  ]
}
```

成功后返回与详情相同的 `{ id, name, questions }`，并在持久化提交成功之后才返回成功。前端只有收到完整、合法的成功详情才能提示“模板已保存”。新建失败不得清空当前岗位题目或显示保存成功。

模板名称先 `trim`，去除首尾空白后须为 1 至 80 个 Unicode 码点；不能按 JavaScript UTF-16 长度或 UTF-8 字节数代替。后端需采用相同计数规则。在授权团队范围内，名称唯一性至少按 `trim` 后名称判定；是否还需大小写或 Unicode 规范化须由维护者明确，并同步前后端。

同名创建须返回业务码 `409`，拒绝覆盖旧模板，不做静默更新或自动加后缀。后端应用校验和数据库唯一约束应共同处理并发同名创建，确保两个管理员同时提交同名模板时至多一个成功。

## 题目定义及校验

题目与当前 `AdminView.vue` 编辑器字段一致。每道模板题目仅包含以下六个字段，前后端通过白名单构造对象：

| 字段 | 类型及规则 |
| --- | --- |
| `sortOrder` | 正整数，按 `questions` 数组次序连续为 `1..N`，不允许重复、缺号或任意旧排序值 |
| `title` | 字符串，`trim` 后非空；不得把空白标题保存为有效题目 |
| `questionType` | 仅 `TEXT`、`TEXTAREA`、`RADIO`、`CHECKBOX`、`FILE_UPLOAD` |
| `options` | 独立的字符串数组；单选、多选至少一项且每项 `trim` 后非空；其他题型为 `[]` |
| `required` | JSON 布尔值，不能用 `"true"`、`"false"`、`0`、`1` 替代 |
| `placeholder` | 字符串，无提示时为 `""` |

`questions` 必须为非空数组。前端整理并验证当前编辑题目后再发起创建请求；服务端仍需独立执行全部校验，不能把前端校验视为可信边界。选择项按数组分别传递，不能拼接成逗号字符串或 JSON 字符串；包含逗号的选项仍是一项。

模板题目不包含 `id`、`jobPostId`、申请人、答案、上传文件 ID、下载地址或其他业务对象引用。`FILE_UPLOAD` 只保存“文件上传”题型定义，不保存学生已上传文件。后端不得持久化这些越界字段；建议对包含答案或文件引用的请求直接返回 `400`，避免误用。模板内容与原岗位分离，后续修改原岗位不会改变模板快照。

## 应用到岗位及已有答案保护

“应用模板”读取服务端详情并将题目定义深拷贝到当前表单；每题重新按 `1..N` 排序，每个 `options` 数组独立复制。更改表单选项不能改变列表缓存、模板内容或其他岗位。应用取代当前表单题目，已有题目时需由前端明确提示覆盖当前编辑内容；它不复制原题目 ID、岗位 ID、答案或文件 ID。

应用本身没有新增写接口，不创建或保存岗位、不发布岗位，也不回写或修改模板。保存模板同样不保存或发布当前岗位。管理员仍通过原有“保存草稿”或“发布岗位”动作提交岗位及题目。

| 当前编辑对象 | 是否可应用 |
| --- | --- |
| 尚未保存、没有岗位 ID 的新岗位 | 可以，结果仅留在当前编辑表单 |
| 已有岗位，`status === "OFFLINE"` 且 `applicationCount` 明确为数值 `0` 或字符串 `"0"` | 可以，但提交时服务端仍须再次确认 |
| 已有岗位，`applicationCount` 缺失、`null`、空串、仅空格、布尔值、非法数字或正数 | 禁止；缺失不能默认为零 |
| 已发布、推荐中、已结束等任何非 `OFFLINE` 岗位 | 禁止，即使返回零投递 |

资格判定使用服务端返回的原始岗位状态与明确的投递数，不能使用列表展示层的 `applicationCount ?? 0`、`apps` 默认值或 `Number(value)` 宽松转换来证明“零投递”。界面启用按钮不是服务端授权或一致性保证。

当前前端已有保存流程使用客户端路径 `PUT /admin/job-post/{id}` 更新岗位，并使用 `POST /admin/questionnaire/questions/batch/{id}` 提交题目；默认完整路径分别为 `/api/admin/job-post/{id}`、`/api/admin/questionnaire/questions/batch/{id}`。新岗位先通过 `POST /admin/job-post` 创建。以上是当前前端调用，实际 Java 后端仍须联调确认。

**模板界面限制不能解决原有批量题目保存的安全性。** 如果实际后端仍按“删除旧题目，再插入新题目”实现 batch 接口，旧题目 ID 会改变，可能破坏已有答案与题目的关联。不得因为题目内容相同、前端未显示模板入口或列表投递数是零就认为可以安全替换。

后端必须在岗位提交及题目写入时从数据库重新检查最新状态、真实投递和已有答案，拒绝会破坏已提交答卷的替换，并返回明确冲突错误。必须处理“打开编辑器时零投递、保存前已有新投递”的竞态；检查和写入需通过事务、锁或版本条件形成一致性保护，不能检查后再无保护地删除。对非草稿岗位仅修改普通岗位字段时，应保留原题目及答案关联，避免无变化的 batch 重存也重建题目 ID。

当前岗位与题目分两次请求保存，并不天然保证整体原子性。维护者需确认事务/版本方案及失败恢复；第二次请求失败时前端不能宣称整份岗位和问卷都已保存或发布。若需要调整现有保存契约，须双方确认后再实现，不由本文假定已修复。

## 失败响应与用户反馈

错误仍使用统一 JSON 封装，例如：

```json
{
  "code": 409,
  "message": "模板名称已存在，请更换名称",
  "data": null
}
```

| HTTP 状态 / 业务码 | 处理要求 |
| --- | --- |
| `400` | 名称、题目、题型或数据类型不合法；指出可修正原因 |
| `401` | 未登录或登录失效；沿用统一身份失效处理 |
| `403` | 已登录但无管理员或团队权限；拒绝请求 |
| `404` | 模板不存在或按权限策略不可见；提示重新加载 |
| `409` | 同名创建冲突；已有岗位状态/投递变化导致题目不能替换时也返回明确冲突消息 |
| `5xx` | 服务或存储故障；不返回伪成功，允许用户保留编辑内容后重试 |

断网、超时、空响应、非 JSON 或结构异常同样按失败处理。`data: null`、错误分页对象、缺少题目、未知题型、不安全数字 ID 等不能伪装成合法空列表或成功模板。区分“库中确实没有模板”和“列表加载失败”，并提供重试。创建超时后不能断言服务端一定未保存；重试前可重新查询，已存在时按同名冲突处理。

## 后端维护者实施清单

以下为实现和联调清单，尚未执行数据库迁移，也未修改任何后端代码。

- 确认实际 Java 后端仓库、部署分支、`/api` 网关映射、`Fusion-Token` 认证和当前登录身份接口；对齐 `ADMIN`、`SUPER_ADMIN` 与团队授权模型。
- 为三个拟议模板接口实施每次请求的服务端身份及权限校验，并统一成功和失败 JSON 封装。
- 建立服务端持久化及事务提交；建议模板表保存字符串化输出的主键、团队范围、规范化名称、创建人和创建时间，题目以独立明细或 JSON 快照保存。此结构仅为建议，具体 DDL、存储方案及迁移由维护者审核实施。
- 对授权团队内规范化名称建立唯一约束；并发冲突转换为业务 `409`，禁止覆盖旧快照。
- 使用题目字段白名单及严格类型校验，保存独立的完整快照；禁止答案、申请人及文件引用进入模板存储。
- 固定列表数组结构、稳定排序、真实题目数及字符串 ID 序列化；详情仅返回有权读取的模板。
- 审核现有岗位更新和题目 batch 实现，在数据库层保护已有答卷，处理检查到保存间的竞态及分步提交失败；不以模板新增接口代替这项修复。
- 以真实账号、浏览器和数据库完成下述联调，记录实际部署版本及结果后再宣称团队共享可用。

## 验收与验证边界

前端函数测试、组件测试和使用夹具或拦截响应的浏览器测试，只能证明前端的请求、数据整理、交互及失败处理。它们不能证明生产 Java API 已存在、身份权限有效、模板已落库、不同管理员能共享或已有答案安全。

1. 真实管理员 A 创建包含五种题型的模板；检查请求只含 `name` 和六字段题目定义，服务端返回精确字符串 ID。刷新页面及重启后端后仍可读取，题目数量、顺序、选项、必填和提示完整一致。
2. 管理员 B 使用第二个独立浏览器/设备登录同一授权团队，读取 A 创建的模板并应用。两端均从真实 API 读取，不能复用夹具、共享页面内存或复制浏览器存储来冒充持久化；如有多个团队，跨团队账号不可读取。
3. 分别测试未登录、过期 Token、普通学生及无团队权限账号直接请求三个接口；应返回 `401`/`403` 或已确认的隐藏资源策略，绕过前端入口也不能访问。
4. 名称测试空白、80/81 个 Unicode 码点、含补充平面字符、首尾空格、同名及两个管理员并发同名；确认码点计数与唯一性一致，原模板保持不变，冲突返回 `409`。
5. 非法题目测试空数组、空白标题、未知题型、非布尔 `required`、非字符串提示、空选项及混合类型选项、重复/跳号排序；服务端拒绝。尝试附带 `id`、`jobPostId`、答案和文件 ID，确认越界数据未存入模板。
6. 使用 `"9007199254740993"` 等超过 JavaScript 安全整数的 ID，检查创建、列表、详情路径和选择均不变号。让服务端返回不安全数字 ID、错误列表对象、缺字段详情或空响应，前端应失败而非应用错误模板。
7. 新岗位应用后改动题目和选项，再次加载同一模板及另一岗位，确认各份数据独立。应用动作不得发出岗位保存/发布请求，保存模板也不得隐式提交岗位；离开未保存表单不代表模板已应用并落库。
8. 已有 `OFFLINE` 岗位分别返回 `applicationCount: 0`、`"0"`、缺失、`null`、`""`、空格、`false`、`true` 和正数；只有两种明确零值可应用。非草稿即使零投递也不可应用。
9. 编辑器打开后，另一个会话新增投递或修改岗位状态，再保存问卷；服务端应拒绝冲突，已有答案和旧题目 ID 保持可关联。对已有答卷岗位仅改普通岗位信息，确认没有因 batch 重建题目而损坏历史答卷。
10. 模拟列表、详情、创建的断网、`400`、`401`、`403`、`409`、`5xx`、格式异常和持久化失败；检查明确报错、重试及原编辑内容保留。模拟岗位保存成功而题目保存失败，确认没有整份保存/发布成功的误导提示。

只有真实后端部署并完成上述 API、存储、权限及跨浏览器验收后，才可把“前端已完成”推进为“团队共享问卷模板已完成联调”。本文的请求示例和建议表结构本身不构成后端完成证明。
