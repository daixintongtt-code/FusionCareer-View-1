# 学生端岗位浏览与联调约定

本次修改范围是学生端岗位列表、筛选恢复、分页跳转、单位信息展示和收藏入口。前端实现及单元测试不能证明生产后端已经支持新增筛选条件；上线前必须完成本文件中的接口联调。

**当前后端尚未确认“大厂”“学院内推”字段。`jobTags = ["BIG_COMPANY", "COLLEGE_REFERRAL"]` 和分页响应中的 `filterCapabilities.jobTags` 是本次提出、待后端采纳的新增约定，不是仓库已有 API。** 前端只有收到 `filterCapabilities.jobTags === true` 才允许发送标签筛选；缺失、`false`、字符串 `"true"` 或数字 `1` 都不代表支持。

## 状态恢复与分页

- 地址栏使用 `/home` 的 Hash 路由 query 保存 `keyword`、`province`、`city`、`category`、`recruit`、`duration`、`days`、`salary`、`mode`、`tags`、`sort`、`page`。标签编码为逗号分隔的枚举值。
- 同一标签页的 `sessionStorage` 按当前登录账号保存同样的状态和滚动位置；进入详情、收藏或个人中心前保存快照，返回无筛选 query 的 `/home` 时恢复。
- URL 中只要包含一个有效的浏览状态键，就以整个 URL 状态为准，不与旧快照逐字段合并；该状态与快照一致时才恢复旧滚动位置。分享链接中的筛选状态由 URL 决定，账号隔离仅针对本地快照。
- 非法枚举、错误省市组合、未知标签会被清理；页码只接受安全正整数，默认第 1 页。关键词去掉首尾空格并限制为 200 字符。
- 改变任意筛选条件或排序回到第 1 页；仅翻页保留筛选和排序。输入页码必须在 `1..总页数` 内，空值、负数、小数、超界值不发起翻页。
- 总页数按接口 `total` 与每页 10 条计算，末页不满 10 条时仍可访问；筛选后原页码超过末页时请求新的末页。0 条数据展示空结果，不展示无效页码跳转。
- 浏览器禁止 session 存储或写入失败时，URL 和当前标签页内存仍可用于返回恢复。此降级不保证刷新、关闭标签页或换设备后还能恢复滚动位置。

## 岗位列表请求

前端通过统一 API 客户端发送 `GET /api/job/list`。以下是本次前端准备发送的字段；枚举沿用现管理端表单，**生产后端的查询参数支持、日薪单位和排序行为仍需逐项确认**。

- `page`：从 1 开始；`size`：10。
- `keyword`：岗位/单位关键词。
- `workProvince`、`workCity`：省市；选择新省份会清除原城市。
- `jobCategory`：`MEDIA`、`ENTERPRISE`、`GOVERNMENT`、`ACADEMIC`、`OTHER`。
- `recruitType`：`BIG_INTERNSHIP`、`SMALL_INTERNSHIP`、`DAILY_INTERNSHIP`、`CAMPUS_RECRUITMENT`。
- `workPeriodType`：`LESS_THAN_THREE_MONTHS`、`THREE_TO_SIX_MONTHS`、`MORE_THAN_SIX_MONTHS`。
- `workDurationType`：`ONE_TO_TWO_DAYS`、`THREE_TO_FOUR_DAYS`、`FIVE_DAYS`，表示每周天数区间；不发送旧的 `DAYS_3` 或字面数字。
- `workMode`：`ONLINE`、`OFFLINE`、`HYBRID`。
- `sortBy`：`NEWEST` 显示“最新发布 / 发布时间从新到旧”；`DEADLINE` 显示“结束时间 / 投递结束时间从早到晚”。后端需确认真实发布时间字段、无截止日期的顺序及同值时稳定排序，推荐使用唯一岗位 ID 作第二排序键。

`workPeriodType`、`workDurationType`、`workMode` 仅在大/小实习筛选下使用；切换到其他招聘类型会清除这些隐藏条件。历史展示值 `CAMPUS_SCREENING` 与 `BOTH` 只作展示兼容，不作为新增提交枚举。

后端必须对完整结果集先筛选、再排序、最后分页，`total` 返回同一筛选条件下全集的岗位数。前端不会对已分页的 10 条岗位再过滤并将剩余数冒充总数。

## 日薪筛选

当前管理端的 `salaryMin`、`salaryMax` 输入明确标注“元/天”；本次日薪筛选沿用这一数值字段约定，不从 `salaryDisplay` 解析数字，更不将月薪、面议或补贴说明换算为日薪。

当前前端档位和请求边界如下，上下界按闭区间发送，档位以整数日薪设计：

- `under100` → `salaryMin=0&salaryMax=99`。
- `100to149` → `salaryMin=100&salaryMax=149`。
- `150to199` → `salaryMin=150&salaryMax=199`。
- `200plus` → `salaryMin=200`，不发送 `salaryMax`。
- 不限日薪时两个参数都不发送。

整数边界 99/100、149/150、199/200 不重叠。若生产数据允许小数日薪，99.5 等数值不能按当前整数档位完整覆盖，需与后端统一边界表达方式后再启用小数薪资筛选。

联调时还需确认：是否只有公开的结构化薪资参与筛选；缺少数值日薪是否排除；岗位自身是薪资区间时采用“与筛选区间相交”还是“完全包含于筛选区间”。这些行为不能只凭参数同名视为已经对齐。建议采用区间相交并明确单边空值含义，但以最终双方确认的 API 为准。

## 大厂、学院内推：待采纳的新增标签约定

推荐后端新增以下可选响应字段：

```json
{
  "code": 200,
  "data": {
    "list": [
      {
        "id": "9223372036854775807",
        "positionName": "产品实习生",
        "companyName": "示例单位",
        "jobTags": ["BIG_COMPANY", "COLLEGE_REFERRAL"]
      }
    ],
    "total": 1,
    "filterCapabilities": { "jobTags": true }
  }
}
```

上例是**提议的新增响应**，不是已经核验的生产响应。`jobTags` 由后端根据可靠数据来源赋值；需要管理员如何维护标签、哪些岗位属于大厂及学院内推，也必须明确。

- 前端只从岗位的 `jobTags` 数组读取已知值；字符串、未知值不会被当成已确认标签。
- `recommended=true` 仅用于已有推荐岗位入口；它不能推断“学院内推”。`sourceType`、`recruitType=BIG_INTERNSHIP`、单位名称同样不能推断这两个标签。
- 仅返回岗位 `jobTags` 不能证明服务端支持标签查询；分页响应必须显式提供 `filterCapabilities.jobTags: true` 才开放筛选。
- 建议请求为 `jobTags=BIG_COMPANY,COLLEGE_REFERRAL`；**多选按 AND 匹配**，即岗位须同时拥有两个标签。后端如采用其他语义，需先修改约定和界面提示。
- 标签与关键词、省市、类型、日薪共同筛选完整结果集；`total` 返回所有条件筛选后的总数，再按选定排序分页。
- 打开含标签的保存 URL 时，前端先请求一次不带标签的列表以发现能力。支持时再发送带标签请求；不支持时显示“选中的岗位标签暂不可用，请清除标签后重试”，不把探测取得的未筛选列表展示为标签筛选结果。
- 能力缺失或失效时，标签按钮禁用；已有标签可通过条件芯片清除。保持显式失败，避免不支持的查询被后端忽略后误导用户。

## 收藏边界

目前没有确认可用的后端收藏接口。收藏是**按登录账号隔离的当前浏览器 `localStorage` 数据**，不属于服务器持久化，跨浏览器、跨设备不会同步；清除网站存储会删除收藏。

列表和详情页提供收藏按钮，“我的收藏”入口进入个人中心收藏页；同一账号在同一浏览器的相关页面应同步显示收藏状态。登录账号身份及当前 Token 校验通过后才可写入；换账号不读取旧的共享收藏列表，退出登录或 Token 失效后不允许继续收藏。长整型账号及岗位 ID 应以字符串传输，避免 JavaScript 数值精度丢失。

存储读取或写入失败应显示失败反馈，并保留原收藏数据，不显示“收藏成功”。收藏记录是保存时的摘要，点击后仍请求实时岗位详情；岗位下线、删除或内容变化需按详情接口结果处理，不能把摘要当成实时岗位状态。

## 验收步骤

1. 登录学生 A，设置关键词、省市、岗位大类、大/小实习、时长、每周天数、工作形式、日薪、排序，跳至第 2 页及后续页；进入岗位详情，分别通过“岗位列表”和浏览器返回，检查所有条件、页码及滚动位置恢复。刷新带 query 的列表再次检查条件和页码；用另一套 query 打开列表，确认 URL 优先。
2. 修改筛选与排序，检查页码回到 1；仅翻页保持其他条件。省份改变后旧城市清空，招聘类型改变后隐藏的实习条件清空。直接输入非法枚举、跨省城市、未知标签和异常页码 URL，应清理且不发送非法 API 条件。
3. 后端准备 0、1、10、11、20、21 条匹配岗位，检查总数、末页、下一页按钮和页码跳转；空值、0、负数、小数、超出末页时显示输入错误，地址栏和列表保持原页。模拟岗位下线导致总页数减少，检查跳转到当前末页。
4. 后端准备整数日薪 0、99、100、149、150、199、200，以及仅有月薪文字、面议、空数值的岗位；逐档检查请求上下界及结果。另准备日薪区间和 99.5 的样例，记录实际匹配语义并完成单位/边界联调，不靠文字中出现的数字判定通过。
5. 后端未支持标签时，检查两个标签按钮禁用；打开含标签的 URL 不应显示普通列表为筛选结果。分别返回缺失能力、`false`、`"true"`、`1`，都不可开放标签。仅 `true` 时可用。
6. 后端支持新增约定后，准备无标签、只有大厂、只有学院内推、同时两项标签的岗位，且让匹配岗位跨越多个原始页；检查单选、多选 AND、全局排序、分页与 `total`。只有 `recommended`、`sourceType` 或 `BIG_INTERNSHIP` 的岗位不得展示这两个标签。
7. 检查岗位列表及推荐卡片的单位名称、岗位名称层级，长单位名称可阅读；在窄窗口和 200% 缩放下确认筛选、页码跳转、收藏按钮仍能操作，分页不被右下角浮钮遮挡。核对“最新发布”与“结束时间”的说明和后端实际顺序一致。
8. 学生 A 在列表收藏、详情取消、个人中心取消，检查页面状态一致；退出并登录学生 B，不应看到 A 的收藏或无 query 的浏览快照。再次登录 A 可读取本浏览器原收藏。换设备不应宣称可同步。
9. 模拟 session 存储禁用，列表到详情再返回仍能使用 URL/同标签页内存恢复；模拟 localStorage 读写失败，收藏报错且不覆盖原记录。模拟岗位列表 500/断网/响应格式错误，显示加载失败和重试，不显示“共 0 个岗位”作为空搜索结果。

## 自动化验证范围

运行 `npm test`，其中 `test/job-browse.test.mjs` 覆盖状态及 URL 编码、输入清理、账号隔离快照、禁用存储、分页边界、请求字段、整数日薪边界和严格标签能力；`test/favorites.test.mjs` 覆盖本地收藏隔离、存储失败及真实组件的身份初始化和重试。`test/home-lifecycle.test.mjs` 执行真实列表组件 setup，覆盖卸载后的迟到响应和滚动、账号切换及 401 重试；`test/auth-session.test.mjs` 验证身份缓存和旧请求 401 不影响新 Token。

这些是前端函数测试，不替代生产 API 联调、真实登录浏览器验收或视觉验收；本文件中的待采纳字段及待确认行为通过联调前，不应写成“后端已完成”或“生产已上线”。
